# sonarqube_project (Resource)

Provides a Sonarqube Project resource. This can be used to create and manage Sonarqube Project.


## Example Usage
### Example: create a project
```terraform
resource "sonarqube_project" "main" {
  name       = "SonarQube"
  project    = "my_project"
  visibility = "public"
}
```

### Example: a project with associated settings
```terraform
resource "sonarqube_project" "main" {
  name       = "SonarQube"
  project    = "my_project"
  visibility = "public"

  setting {
    key   = "sonar.demo"
    value = "sonarqube@example.org"
  }
}
```

### Example: manage a project without retrieving its badge token
```terraform
resource "sonarqube_project" "without_badge_token" {
  name                 = "My project"
  project              = "my-project"
  visibility           = "private"
  retrieve_badge_token = false
}
```

Setting `retrieve_badge_token = false` skips the badge-token endpoint and clears the value from subsequent state snapshots. It does not revoke the server-side badge token or remove historical state snapshots and saved plans. Retrieval remains enabled by default.

For an import that must not retrieve the badge credential, use `terraform import sonarqube_project.example 'my-project?retrieve_badge_token=false'`. An ordinary project-key import preserves the default behavior and retrieves the badge token; configuration alone is not available to the importer.

## Migration: sensitive badge-token outputs

`badge_token` is now marked sensitive on both the project resource and the project data source. Existing root outputs that expose either attribute must declare `sensitive = true`; otherwise Terraform rejects the output during planning.

```terraform
output "project_badge_token" {
  value     = sonarqube_project.main.badge_token
  sensitive = true
}

output "existing_project_badge_token" {
  value     = data.sonarqube_project.project.badge_token
  sensitive = true
}
```

Marking an output sensitive redacts its normal display; it does not remove the value from state or saved plans.

To stop retrieving and storing the badge token, set `retrieve_badge_token = false` on each relevant resource or data source and remove outputs and consumers that require its value. This clears the value from subsequent state snapshots without revoking the server-side token or changing historical snapshots and saved plans.

## Schema

### Required

- `name` (String) The name of the Project to create. Changing it creates a new project, which loses the project's analysis history, because SonarQube has no API to rename a project. To rename one, let the next analysis set the name through `sonar.projectName` and add `lifecycle { ignore_changes = [name] }`.
- `project` (String) Key of the project. Maximum length 400. All letters, digits, dash, underscore, period or colon. Changing it updates the key in place and keeps the project's history.

### Optional

- `retrieve_badge_token` (Boolean) Retrieve and store the project's badge token. Set to false to omit it from state and avoid calling the badge-token endpoint. Existing state history is not changed.
- `setting` (Block List) A list of settings associated to the project (see [below for nested schema](#nestedblock--setting))
- `tags` (List of String) A list of tags to put on the project.
- `visibility` (String) Whether the created project should be visible to everyone, or only specific user/groups. If no visibility is specified, the default project visibility of the organization will be used. Valid values are `public` and `private`.

### Read-Only

- `badge_token` (String, Sensitive) The badge token for the project.
- `id` (String) The ID of this resource.
