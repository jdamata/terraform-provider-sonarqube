# sonarqube_project (Resource)

Provides a Sonarqube Project resource. This can be used to create and manage Sonarqube Project.


## Example Usage
### Example: create a project
```terraform
resource "sonarqube_project" "main" {
  name       = "SonarQube"
  project    = "my_project"
  visibility = "public"
}
```

### Example: a project with associated settings
```terraform
resource "sonarqube_project" "main" {
  name       = "SonarQube"
  project    = "my_project"
  visibility = "public"

  setting {
    key   = "sonar.demo"
    value = "sonarqube@example.org"
  }
}
```

### Example: manage a project without retrieving its badge token
```terraform
resource "sonarqube_project" "without_badge_token" {
  name                 = "My project"
  project              = "my-project"
  visibility           = "private"
  retrieve_badge_token = false
}
```

Setting `retrieve_badge_token = false` skips the badge-token endpoint and clears the value from subsequent state snapshots. It does not revoke the server-side badge token or remove historical state snapshots and saved plans. Retrieval remains enabled by default.

## Optional early migration: sensitive badge-token outputs

`badge_token` remains non-sensitive by default on the project resource and data source, preserving existing badge-URL outputs. To opt in to sensitive outputs before the next major version, set the feature flag in the environment running Terraform:

```shell
export SONARQUBE_BADGE_TOKEN_SENSITIVE=true
```

The flag is disabled by default; only the literal `true` enables it. It selects the provider schema before configuration, applies to every provider alias in the process, and must have the same value for plan and apply, including CI and remote execution environments. It is not a provider configuration argument.

When enabled, root outputs exposing `badge_token`, including badge URLs built from it, must declare `sensitive = true`; otherwise Terraform rejects the plan.

```terraform
output "project_badge_token" {
  value     = sonarqube_project.main.badge_token
  sensitive = true
}

output "existing_project_badge_token" {
  value     = data.sonarqube_project.project.badge_token
  sensitive = true
}
```

Sensitivity redacts normal display; the value still exists in state and saved plans. Set `retrieve_badge_token = false` on each relevant resource or data source to skip retrieval and clear the value from subsequent state snapshots. This does not revoke the server-side token or change historical snapshots and saved plans.

## Schema

### Required

- `name` (String) The name of the Project to create. Changing it creates a new project, which loses the project's analysis history, because SonarQube has no API to rename a project. To rename one, let the next analysis set the name through `sonar.projectName` and add `lifecycle { ignore_changes = [name] }`.
- `project` (String) Key of the project. Maximum length 400. All letters, digits, dash, underscore, period or colon. Changing it updates the key in place and keeps the project's history.

### Optional

- `retrieve_badge_token` (Boolean) Retrieve and store the project's badge token. Set to false to omit it from state and avoid calling the badge-token endpoint. Existing state history is not changed.
- `setting` (Block List) A list of settings associated to the project (see [below for nested schema](#nestedblock--setting))
- `tags` (List of String) A list of tags to put on the project.
- `visibility` (String) Whether the created project should be visible to everyone, or only specific user/groups. If no visibility is specified, the default project visibility of the organization will be used. Valid values are `public` and `private`.

### Read-Only

- `badge_token` (String) The badge token for the project.
- `id` (String) The ID of this resource.

## Import

Import an existing project using its project key:

```shell
terraform import sonarqube_project.example 'my-project'
```

An ordinary import retrieves the badge token. To skip retrieval during import, append `?retrieve_badge_token=false`:

```shell
terraform import sonarqube_project.example 'my-project?retrieve_badge_token=false'
```

Also set `retrieve_badge_token = false` in the resource configuration to keep retrieval disabled on later refreshes. The CLI importer cannot read that configuration, so the suffix is required to avoid retrieving the credential during import itself.
